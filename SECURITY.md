# Security policy

Please do not post active vulnerability details, exploit steps, credentials, or sensitive logs in public issues, discussions, or pull requests.

## Reporting

Use GitHub’s **Report a vulnerability** option in the Security tab of the affected repository when private vulnerability reporting is enabled. For setup details, see [GitHub’s security policy guidance](https://docs.github.com/en/code-security/getting-started/adding-a-security-policy-to-your-repository).

If that option is unavailable, do not disclose the details publicly. Ask an organization maintainer through a private channel you already trust to provide a safe reporting route. No dedicated security email address is currently published. Do not send passwords, private keys, or unrelated personal data.

Include only what is needed to reproduce and assess the issue. Give maintainers reasonable time to investigate and coordinate a fix before any public disclosure.

Organization maintainers should enable GitHub private vulnerability reporting for public project repositories where available and publish a monitored private contact route.
