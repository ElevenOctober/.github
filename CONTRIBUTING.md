# Contributing

You can contribute without formally joining the organization. Contribution is more important than title.

## Ways to help

- Report a real engineering problem through the [problem form](https://github.com/ElevenOctober/.github/issues/new?template=problem-submission.yml).
- Work on an accepted problem, reproduce a result, test hardware, review firmware or schematics, or analyze measurements.
- Design PCBs, write software, improve documentation, create diagrams, or help write an Open Engineering Article.
- Review prior work, datasheets, papers, licenses, and safety constraints.

New project ideas are not accepted as problem reports. A problem must come from an identifiable external source and have reasonable evidence that it exists.

## Before proposing a change

1. For project work, identify the accepted Problem ID and read its source, requirements, constraints, and current status.
2. Check existing approaches and licenses before reusing code, designs, datasets, or text.
3. For engineering proposals, use the proposal form and connect it to an accepted Problem ID.
4. For documentation corrections, use the documentation form or open a focused pull request.

## Contributor expectations

- Be respectful and discuss technical disagreements with evidence.
- Record important decisions and cite external work.
- Respect licenses and requesters’ privacy.
- Report failures and measurements honestly; do not fabricate provenance, benchmarks, or results.
- Make work reproducible where practical and state what is needed to reproduce it.
- Consider safety before building or testing anything that can cause physical harm.

Read the [Code of Conduct](CODE_OF_CONDUCT.md), [problem lifecycle](docs/PROBLEM_LIFECYCLE.md), [project standard](docs/PROJECT_STANDARD.md), and [attribution policy](docs/ATTRIBUTION.md) before publishing project work.
